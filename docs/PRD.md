# PRD: 팀 프로젝트를 위한 팀 편성 웹 앱

## 1. 목적
학생들이 팀 프로젝트 팀을 스스로 편성한다. 모집 마감 뒤 남은 학생은 AI가 배정안을 내고, 앱이 그 배정안을 규칙으로 검사한 뒤 관리자가 확정한다.

## 2. 사용자
| 사용자 | 하는 일 |
|---|---|
| 학생(명단 CSV의 가상 학생) | 학번과 비밀번호(1234)로 로그인, 팀 목록과 팀원 역할 보기, 팀에 지원, 내 팀에 들어온 지원에 찬성 또는 거부 |
| 관리자(학번 admin) | 명단 CSV와 팀 수로 처음 상태 만들기, 모집 마감, AI 배정, 배정안 확정 |

## 3. 규칙
- 역할 6개: 기획자, 웹 프로그래머, 프론트엔드 디자이너, 테스터, 보고서 작성자, 발표자. 학생마다 주 역할 1개, 보조 역할 0~2개.
- 확정한 팀은 2~4명이다.
- 한 팀 안에서 주 역할이 겹치면 안 된다.
- 모든 팀에 기획자와 웹 프로그래머를 맡을 학생이 서로 다른 사람으로 있어야 한다. 주 역할이나 보조 역할로 맡을 수 있다.

## 4. 기능 요구사항
1. 로그인: 비밀번호는 bcrypt 해시로 저장한다. 관리자 계정은 앱이 시작할 때 ADMIN_PASSWORD로 만들거나 갱신한다.
2. 지원
   - 빈 팀에 지원하면 바로 승인한다.
   - 팀원이 있는 팀에 지원하면 대기하고, 지금 팀원 모두의 투표를 기다린다.
   - 다음 경우에는 지원을 막는다: 팀이 꽉 참, 같은 주 역할의 팀원이 있음, 이미 팀이 있음, 결과를 기다리는 지원이 있음, 모집이 마감됨, 필수 포함 역할 자리가 모자람.
3. 투표
   - 한 명이라도 거부하면 바로 거절한다. 모두 찬성하면 승인한다.
   - 승인 직전에 규칙을 다시 검사한다.
   - 한 번 한 투표는 바꿀 수 없다.
4. 마감
   - 대기 중인 지원을 거절한다.
   - 1명뿐인 팀의 학생을 팀에서 뺀다.
5. 배정
   - 오픈라우터 모델 1차, 2차, 3차를 차례로 부른다. 모델마다 전체 120초 제한을 둔다.
   - 배정안이 다섯 가지 검사를 통과하지 못하면 다음 모델로 넘어간다.
   - 3차 모델까지 실패하면 앱이 모든 경우를 따져 배정을 찾는다.
   - 규칙을 지키는 배정이 없으면 이유를 보여 준다.
6. 확정: 검사를 통과한 배정안만 보여 주고, 관리자가 확정하면 DB에 저장한다.
7. 다른 사람의 변경 보기: st.fragment로 3초마다 바뀐 부분을 다시 그린다.

## 5. 비기능 요구사항
- 키, DB 주소, 관리자 비밀번호는 .env와 Streamlit Secrets에만 둔다. 화면에 출력하지 않는다.
- 동시성
  - 상태를 바꾸는 동작은 DB 잠금(advisory lock) 안에서 처리한다.
  - tf_members의 (team_id, slot_no) 기본 키와 student_id 유일성으로 마지막 자리 경쟁을 막는다.
- DB 연결은 연결 풀 하나를 다시 쓴다.
- 화면 요소의 key는 공고 2.7절 표를 따른다. 결과 안내는 승인, 대기, 거절, 막힘 가운데 하나로 시작한다.
- 시각은 한국 시각으로 보여 준다.
- DB 일시정지를 막기 위해 GitHub Actions가 매일 DB에 질의한다.
