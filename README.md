## 3. 고른 해결 방법
| 기능 | 해결 | 설명 |
|---|---|---|
| 다른 사람의 변경 보기 | 어려운 해결 | `st.fragment(run_every=3)`로 3초마다 바뀐 부분만 다시 그림 |
| 필수 포함 역할을 지킬 수 없는 팀 | 어려운 해결 | 지원할 때 남는 자리 수가 아직 못 채운 필수 역할 수보다 적으면 막음 (`engine.join_problem`) |
| 같은 팀에 대기 중인 지원이 여럿 | 어려운 해결 | 마지막 찬성이 들어온 순간 규칙을 다시 검사함. 처리 순서는 투표가 끝난 순서 |
| 마지막 자리에 두 명이 동시에 들어감 | 어려운 해결 | `tf_members`의 (team_id, slot_no) 기본 키와 student_id 유일성 제약(`schema.sql`), DB 잠금 |
| AI 응답이 늦을 때 | 어려운 해결 | 모델마다 전체 대기 시간 120초를 재서 끊고 다음 모델로 넘어감 (`ai.ask`) |
| 3차 모델까지 실패 | 어려운 해결 | 앱이 모든 경우를 따져 다섯 가지 검사를 통과하는 배정을 찾음 (`engine.solve`) |
| AI 대기 중 화면 | 어려운 해결 | "n차 모델 …의 응답을 기다리는 중 · k초"를 1초마다 갱신 |
| DB 일시정지 막기 | 어려운 해결 | GitHub Actions가 매일 DB에 질의 (`.github/workflows/keepalive.yml`) |
